# kcode MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从空仓库交付一个默认拒绝、可侧载的 Chrome MV3 扩展：用户选择本地工作目录后，可在 v86 Alpine Linux 中同时挂载 `/work` 与启用 WISP 完整出站 TCP，并可显式切换 `confirm-each` 或真正的 `auto` ReAct 执行，同时保留变更 journal、结果脱敏、强制停止和资源上限。

**Architecture:** Side Panel 负责风险确认、执行模式、UI、任务状态机和 xterm.js；MV3 background service worker 认证并路由 Side Panel 与目标标签页的 Port；content script 仅通过站点适配器驱动 DeepSeek DOM。每次 Shell 调用使用一个可丢弃的 Dedicated Worker 托管 v86、外层 watchdog、串口执行器、仅持有用户授权目录的 9P 服务，以及按 session 配置的 v86 WISP `net_device`；目录 handle 只经结构化克隆进入 Worker，WISP relay 只接受经校验的用户 `wss://` 配置。`confirm-each` 保留三段式审批；`auto` 在绑定工作区、完整 relay URL 和当前浏览器会话的一次性高风险确认后，自动执行工具、提交 journal 并发送脱敏结果。

**Tech Stack:** Chrome MV3 + Side Panel API、Vue 3.5、TypeScript 7、Vite 8、`@crxjs/vite-plugin` 2.7、v86 0.5.458、xterm.js 6、Vitest 5、Testing Library、Playwright 1.62、File System Access API、IndexedDB、OPFS。

**Spec:** `AI.md`

## Global Constraints

- 网页 AI、网页 DOM、仓库内容、Shell 输出、guest Linux 和 WISP relay 一律视为不可信；v86、9P、background、Side Panel 和浏览器权限共同构成能力边界。
- 首个公开版本只支持 `https://chat.deepseek.com/*`；manifest 权限固定为 `sidePanel`、`storage` 和该站点，不声明 `tabs`、`activeTab`、`<all_urls>` 或全域 `optional_host_permissions`。
- v86 必须运行在 Dedicated Worker；配置 `memory_size: 128 * 1024 * 1024`。每次 Shell 工具结束、超时或异常后终止该 Worker；离线调用从已校验快照启动，网络调用在快照设备拓扑兼容性未经真实测试证明前从已校验 kernel/initramfs 冷启动。
- Linux 工作目录固定挂载为 `/work`；首次选择使用 `showDirectoryPicker({ mode: 'read' })`。写权限只能在用户手势中请求，9P 后端即使已获浏览器写权限也默认保持只读。
- 扩展页 CSP 固定为 `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'; connect-src 'self' wss:; img-src 'self' data:; style-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'`，以支持运行时配置的安全 WISP relay；仍禁止 `ws:`、远程脚本、`eval`、内联 HTML和动态下载后执行代码。`wss:` 扩大了扩展上下文的潜在外连面，必须由严格 URL 校验、唯一网络适配模块和源码扫描约束调用点。
- 执行模式默认 `confirm-each`，用户可显式开启 `auto`。开启 `auto` 或首次让真实工作区联网时集中显示一次高风险确认；确认记录只存 `chrome.storage.session`，并绑定 `workspaceId`、规范化完整 relay URL 和 consent schema。更换目录、relay 或浏览器会话必须重新确认。
- `confirm-each` 的每个工具调用依次完成人工执行/能力授权、文件变更接受或回滚、脱敏结果发送授权。有效 `auto` consent 下不逐工具弹窗：自动授权工具、自动提交 journal、自动发送经过强制扫描/脱敏/截断的结果；取消、敏感路径拒绝、journal 冲突、DLP、资源配额、超时和 Worker 强制终止不可被 `auto` 绕过。
- 单任务最多 20 个 AI 回合，单命令默认 120 秒、最大 600 秒；本地保留输出最多 1 MiB，发送给 DeepSeek 的脱敏结果最多 256 KiB，超过任何流量预算立即终止当前 VM。
- 默认拒绝读取 `.env`、私钥、个人凭据目录和包管理器凭据；MVP 不提供绕过保护路径的 UI。结果扫描只能作为补充，不能替代路径级拒绝；联网 guest 可在 TLS 内直接外传其余可读内容，这一风险无法由结果扫描发现，必须在联网与 `auto` consent 中明确说明。
- MVP 的 9P 语义支持普通文件和目录的遍历、创建、读取、写入、截断、列目录、删除和可恢复的非原子重命名；符号链接、硬链接、设备文件、`chown` 和宿主 POSIX 权限位不在 MVP 内。
- 每个可写工具调用必须创建 OPFS mutation journal；单文件备份上限 16 MiB、单事务 100 MiB。超限写入拒绝执行，未提交事务在重启后必须可回滚。
- 不实现 `network-strip.ts` 或 v86 `fetch` 后端。工作区默认 `offline`；用户启用网络并确认风险后，同一个临时 VM 可同时挂载真实 `/workspace` 和使用 v86 WISP 后端。该能力提供 relay 所允许的 guest 出站 TCP（包括 Git、NPM、curl/HTTPS），不承诺 raw IP、任意 UDP、入站端口或 relay 禁止的目的地址。
- 所有大体积 VM 资产必须由脚本生成或同步并校验 SHA-256；Alpine 基础镜像固定 OCI digest，生成快照前清除历史、临时数据和机器标识。
- 测试顺序遵循 TDD：先看到目标测试因缺少行为而失败，再写最小实现，再跑局部与全量测试。
- 当前目录不是 Git 仓库；Task 1 初始化 Git。后续每个任务只提交该任务列出的文件，不夹带无关改动。

## Scope and feasibility decisions

`AI.md` 是方向性技术草案，不是可以原样编码的接口定义。实施时采用以下已锁定修正：

| 草案设想 | 本计划采用的实现 |
|---|---|
| Side Panel 直接给 content script 传 `onChunk` 回调 | background 维护两个长连接 Port，所有事件携带 `requestId` 路由；Chrome 消息不能克隆函数 |
| 解析一段以太网/TCP payload 后直接 `fetch`，同时支持 443 | 使用 v86 现有 `net_device` 后端；浏览器 `fetch` 无法透明终止任意 guest TLS/TCP |
| `handleWalk/read/write` 即为 9P 服务 | 实现 9P2000.L 帧编解码、fid 生命周期、错误回复、目录读取、属性和变更操作后再接 FSA |
| Alpine 根文件系统也从唯一的 `host9p` 启动 | Alpine 作为 initramfs/静态快照启动，把 v86 的 `host9p` 留给 `/workspace` |
| 用递归 `stepLoop` 无限运行 | 用显式状态机和 `while` 循环，加入回合上限、超时、取消和单工具调用约束 |
| 一开始申请 `<all_urls>` | 公开 MVP 只申请 DeepSeek；删除 `tabs` 和所有全域 host 权限 |
| 工具结果自动回传网页 AI | `confirm-each` 先扫描、预览并人工发送；`auto` 强制扫描/脱敏/截断后自动回传，永不提供发送检测到的原文选项 |
| 一次启动 VM 并在多回合间持续复用 | 每个 Shell 调用使用临时 VM，结束或超时立即销毁，后台进程不能跨工具存活 |
| 宿主目录与 guest 网络同时开放 | 使用 v86 WISP backend 提供完整 guest 出站 TCP；允许与真实 `/workspace` 同时启用，但默认关闭并要求绑定工作区与 relay 的会话级风险确认 |

验收基线是 Chrome 116+ 的开发者模式侧载。第一版不承诺跨浏览器、后台常驻 VM、raw IP、任意 UDP、入站端口、Git 子模块/符号链接完整语义或 relay 自身的可用性与隐私；在已确认的 `auto` session 内允许无人值守工具执行、工作区联网和脱敏结果自动外发。

## Security invariants

以下约束必须由类型、运行时检查和负向测试同时证明；文档警告不能替代执行时强制：

1. `WorkspaceSession` 始终包含独立的 `network: { mode: 'offline' } | { mode: 'wisp'; relayUrl }`；目录 handle 只能通过 `VM_ATTACH_WORKSPACE` 单独发送，不能进入 Chrome Port 或持久化配置。`network.mode === 'wisp'` 只有在 relay URL 校验通过且当前 `workspaceId + relayUrl` 有 `workspace-networked` consent 时才能启动。
2. background 只接受本扩展的 Side Panel 和 DeepSeek 顶层 frame，所有 content 事件的 tab ID 由 `port.sender.tab.id` 覆盖，页面提供的身份字段不参与授权。
3. VM 收到目录 handle 后仍默认只读；只有当前已审批事务的 `write`/`delete` capability 才能放行对应 9P 操作。
4. Shell 串口 nonce 只用于分帧，不作为安全边界；真正的终止边界是 Side Panel watchdog 销毁 Dedicated Worker。
5. AI 回复、命令、文件内容和终端输出只能按纯文本渲染；不使用 `v-html`，不自动加载远程资源，剥离 OSC 52、OSC 8 和窗口标题控制序列。
6. 工具结果先留在本地且必须经过敏感信息扫描、脱敏和截断；`confirm-each` 还要求用户预览并批准，`auto` 只允许自动发送处理后的 payload。任何模式都不能发送被检测出的原始敏感值。
7. `RiskConsent` 只能由 Side Panel 用户手势授予并保存在 `chrome.storage.session`；运行每一步前重新核对 consent version、`workspaceId`、规范化完整 relay URL 和 execution mode。缺失、过期或上下文不匹配立即降级为 `confirm-each`/`offline` 并停止当前任务。
8. 任何超时、Port 断开、标签页导航、Worker 崩溃、journal 不完整、安全预算超限或用户点击“一键停止”都采用 fail-closed：停止任务、销毁 VM、不继续外发，并提示恢复/回滚。

```ts
  await dispatcher.resolveChanges(local.transactionId, decision);
  if (decision === 'rollback') return cancelled('CHANGES_ROLLED_BACK');
  const guarded = resultGuard.redact(local.result);
  const released = auto
    ? guarded.redactedText
    : await approvals.requestResultRelease(guarded, signal);
  prompt = `<tool_result id="${escapeAttr(parsed.call.id)}">\n${escapeToolResult(released)}\n</tool_result>`;
}
throw new AgentError('MAX_TURNS_EXCEEDED');
```

Before the first send, run the user's goal through `ResultGuard`; detected secrets are replaced and the UI shows the exact outgoing goal before the user's Start click. The initial system prompt states `/workspace`, the three exact schemas including required bash capability, current offline/WISP state, protected-path denial, one tool call per response, and the need to finish with plain text. Escape `&`, `<`, `>`, quotes, and invalid Unicode before sending results. Semantic prompt injection remains unresolved untrusted data: `confirm-each` relies on review, while `auto` knowingly proceeds under its one-time warning and hard capability boundaries. Use one root `AbortController` per task and reject concurrent `run` calls with `TASK_ALREADY_RUNNING`. Any navigation, router-session change, journal fault, missing interactive approval, or invalid/revoked auto consent ends the loop without another result send.
