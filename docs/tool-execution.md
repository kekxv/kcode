# 工具执行与回归验证

顶部执行模式可直接切换，任务运行中需先停止再切换。

| 模式 | 文件读写 | Shell / 网络工具 | 变更提交 | 脱敏结果发送 |
| --- | --- | --- | --- | --- |
| 手动 | 确认 | 确认 | 确认 | 确认 |
| 自动写入 | 自动 | 确认 | 自动 | 自动 |
| 全自动 | 自动 | 自动 | 自动 | 自动 |

自动模式依然检查工作目录授权、敏感路径和结果脱敏。联网另需启用 WISP。模式授权在停止或工作目录等上下文变化时撤销。

生产 Side Panel 使用持久 VM：相同工作目录、网络和内存配置复用 Worker、9P 挂载及 Shell，因此 `cd` 和环境变量可以跨工具调用保留。`read_file` / `write_file` 的路径始终相对 `/work`，不受 Shell 当前目录影响。停止、超时、运行时错误和配置变化会销毁 VM。低层 API 默认仍支持一次性执行，用于隔离测试及显式短生命周期调用。

`/tmp` 在启动时挂载可写 tmpfs。传输脚本分段上传，工具输出只取 BEGIN/END 边界内的 stdout/stderr，并向模型返回 exit_code。文件完成事件的耗时统一为整数；无效完成事件立即报协议错误，非 Shell 请求设有超时。启动快照写入最多等待 2 秒，存储异常不阻塞已就绪的 VM。

允许说明文字后跟单个完整 `<tool_call>`；聊天气泡保留说明，隐藏完整和流式未完成的工具协议，执行状态由工具卡片显示。多调用混合、无效 JSON、越界路径仍不会执行。

## 验证

```sh
npm run test:run -- tests/unit tests/security tests/simulation
npm run test:run -- tests/integration/vm-smoke.test.ts -t V86Runtime
KCODE_VM_TEST=1 npm run test:run -- tests/integration/vm-persistent.test.ts
npm run build
```

真实 VM 测试启动临时本地 HTTP 服务和独立无头浏览器，使用 OPFS 目录验证 FSA 文件确实写入、提交后读回、连续 Shell 保留 cwd/env、非零退出码和输出清洁度，以及 read 输入、Python REPL、vi 编辑保存、Ctrl+C 中断后环境变量保留。可用 `KCODE_CHROME_PATH` 指向已安装的 Chrome。测试不访问已登录的模型页面；Qwen / DeepSeek 交互另由 `npm run test:qwen` 和 `npm run test:deepseek` 模拟验证。

## 对话界面

工具卡片默认收起，摘要显示操作、目标和状态，点击展开命令或文件内容。回复保留段落、列表与安全的行内格式，并支持复制。底部集中显示当前任务状态及本次已完成工具数。Enter 发送，Shift+Enter 换行，输入法组词期间不发送；运行中可以预写下一任务，停止按钮仅在运行时出现。阅读历史时暂停自动跟随，使用「回到最新消息」恢复。运行日志默认折叠。

## VM Shell 与图片

顶部不再重复浏览器标题，显示实际项目目录、授权状态、连接页面及刷新结果。执行模式菜单包含各模式说明。设置页标题与关闭按钮固定，正文单独滚动。

「终端」使用 xterm.js，支持命令执行、命令历史、停止、清屏和亮暗主题切换。切换主题不重启 VM；在对话下方展开，直接在终端内输入，无需独立命令输入框。支持持续 stdin、Python REPL、read 和 vi，Ctrl+C 中断前台程序并保留 Shell 上下文，Ctrl+D 发送 EOF；「停止」按钮会销毁 VM。每条手动命令最长运行 10 分钟；终端尺寸在命令启动时同步，运行中的全屏程序暂不随面板调整尺寸。终端与 Agent 互斥使用同一 VM。直接运行的命令可以读写、删除已授权目录内的文件，结果仅显示在本地，不交给模型。未连接聊天页面也可运行终端。

对话输入框支持粘贴图片和点击「添加图片」选择文件，最多 3 张 PNG/JPEG/WebP，每张 2 MiB。图片可预览和移除，也可单独发送。图片内容不经过文字脱敏；点击发送会把图片交给当前聊天页面。图片只随首次请求发送，工具结果后续交互不会重复上传，工作记录不保存图片内容。

适配器使用页面原生 file input 或 paste 事件，等待新附件预览/文件名及发送控件就绪。上传入口不唯一、不支持多图或 20 秒内无法确认附件时，不发送任务文字，并显示附件错误。自动化事件的兼容性取决于提供商网页；本地浏览器夹具已验证文件事件和粘贴传递，登录态提供商页面仍需实际验证。

## ChatGPT 会话与终端 CSP

发送新任务前会核对页面中的用户消息：相同工作规则已出现在当前会话时，发送简短的文本执行桥接说明和新任务正文（不附加 User goal 标题），不重复完整工作规则。新会话、清空历史或规则发生变化时重新发送完整规则；不使用标签页级别的永久标记，避免新会话丢失工具说明。无法确认历史时保留完整规则。

ChatGPT 监听区分同一轮的思考与最终消息，读取最终 Markdown 正文；生成标记消失且正文稳定后结束等待，空输入框导致发送按钮禁用不影响收尾。相关回归夹具位于 tests/unit/content/chatgpt-current.test.ts，尚未在登录态 ChatGPT 页面验证。

xterm 的动态主题、字符尺寸样式需要内联 CSS，因此扩展 CSP 的 style-src 允许 unsafe-inline；script-src 仍仅允许本地脚本及 Wasm，不允许内联脚本或 eval。以下真实浏览器测试使用完整扩展 CSP 验证终端渲染、调整尺寸和切换主题，无样式策略违规：

```sh
KCODE_BROWSER_TEST=1 npm run test:run -- tests/integration/terminal-csp.test.ts
```

模型只需输出普通文本形式的工具请求；扩展负责解析、权限确认、VM 执行及结果回传，不依赖聊天提供商的原生工具 API。初始规则和简短提醒均明确要求等待真实 tool_result，不允许模拟执行或编造结果。针对“没有原生工具接口”的误解，编排器最多补充说明一次；仍拒绝该协议则返回 TOOL_BRIDGE_UNAVAILABLE 并标记任务未完成。实际工具错误和一般拒绝不触发此恢复流程。

工具传输现在要求把完整 XML/JSON envelope 放入单个 xml 代码块，解析器兼容该包装以及原来的无代码块格式，防止网页 Markdown 吞掉乘号和下划线。ChatGPT 读取整个消息而非第一个 Markdown 区块；当前回复的复制按钮可确认结束，即使旧 result-streaming 类仍残留，但可见停止按钮仍阻止结束。发现工具文本包含已渲染的强调/删除线时，请求模型重新编码，不猜测丢失的源码字符。

## 精确编辑 edit_file

使用 edit_file（兼容别名 edit）修改已有文件，避免重写整份文件。参数为 path、old_string、new_string，可选 replace_all 布尔值。原文不能为空，默认必须唯一匹配；replace_all:true 替换全部匹配。new_string 为空表示删除。路径限制在 /work，当前文件和写入结果最多 1 MiB；截断读取、未找到、匹配不唯一均不写入。读写在同一变更事务内进行，手动模式展示替换内容并审核变更，自动写入模式自动执行及提交。

```xml
<tool_call>{"id":"edit_1","tool":"edit_file","args":{"path":"index.html","old_string":"20+icell","new_string":"20+i*cell"}}</tool_call>
```

## 连接通道

侧栏连接查询采用经过发送方校验的 chrome.runtime.sendMessage 单次请求，5 秒超时，不复用流式 Port。任务发送、回复增量、完成及取消继续通过 runtime.connect/Port.postMessage 路由。侧栏 Port 断开后在下次请求前重建；内容脚本在连接断开后重新注册。断线中的任务失败退出，不自动重发或重放工具。扩展重新加载使旧内容脚本上下文失效时仍需刷新聊天网页。

ChatGPT 回复定位改为消息节点及标识，避免旧消息虚拟化移除后按历史数量截取导致漏读。兼容 data-turn=assistant 的 article 容器，提取代码块时去除语言标题和复制工具栏。tests/unit/content/chatgpt-current.test.ts 覆盖虚拟化后的完整 XML 工具请求提取、结束和解析。

## 历史任务浏览

侧栏启动时读取当前目录 .session 中的工作记录，并在没有当前消息时展示最新任务摘要。使用「历史任务」选择记录，「新对话」清空本地视图；运行期间禁止切换。恢复记录只读，不自动执行工具，也不导航模型网页。继续输入任务时附加选中记录的任务与结果摘要，并要求重新检查当前文件。现有记录不包含完整消息或工具日志，因此明确标注为摘要恢复。更换项目会重新载入记录；读取错误显示原因，不再因恢复检查失败而清空成功读取的记录。

DeepSeek 长文本处理补充了说明文字后的单个完整 xml/json/text 代码块及 tilde 代码块。仍要求唯一工具调用、完整 JSON 和限额内的 payload，不猜测截断源码。模拟测试覆盖格式修正、DOM 重挂载、长文本写入、结果回传与结束，无效响应之后的读取请求不会被当成最终答复。
